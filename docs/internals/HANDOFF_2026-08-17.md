## Working notes — things that cost time to learn

- **Git through the device bridge leaves lock files it cannot delete.** Every
  `git` call recreates `.git/index.lock` and fails to unlink it, so the *next*
  call fails. Move them aside (`mv .git/*.lock` somewhere) before each git
  operation, and have the user `rm -f .git/*.lock && rm -rf _to_delete` before
  pushing. The bridge cannot delete files at all — only move them.
- **The user's `.venv` symlinks do not resolve through the bridge**, so
  `dissyslab` cannot be imported on their machine from a cloud session.
  Develop against `pip install dissyslab` in the container instead — but that
  is 1.6.1, which ships 20 of the 30 gallery apps. Stage the missing
  `office.md` files to check them.
- **Version your `.skill` bundles when sending them.** Four same-named
  `office-builder.skill` cards were sent; an old one got installed and the
  wrong skill ran for an entire test round. Give each a distinct filename.
- **A skill update can fail silently** — the button reports success and the
  old version stays loaded. Verify by asking something only the current
  version knows.

## The finding worth keeping

A student walkthrough on 2026-08-17 produced a three-tier failure model that
organises everything:

| Tier | Structure | Run | Answer | Instrument |
|---|---|---|---|---|
| 1 | ✗ | — | — | `dsl check` — **exists** |
| 2 | ✓ | ✗ | — | health / hang diagnosis — **missing** |
| 3 | ✓ | ✓ | ✗ | domain check — per-domain only, **missing** in the foundation skill |

Tier 3 cannot be automated in general — no checker knows what the user meant.
The achievable goal is *legibility*: route a filter's rejects to a readable
file rather than to `discard`, so a wrong answer is visible.

And one pattern ran through most of the bugs found: **a document asserted
something the system does not do, and nothing detected the divergence.** The
durable fix is mechanical — a test that every component named in the docs
exists in the registry and vice versa, every `dsl` subcommand named in a skill
exists in `cli.py`, every office in the catalogue is in the built wheel. The
last of those is now in `tests/integration/test_wheel_contents.py`; the others
are not written.
