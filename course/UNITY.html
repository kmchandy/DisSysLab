UNITY

Progress in CTL: the basis rule, transitivity, and fair execution

UNITY is the programming notation and logic of Chandy and Misra. This lecture describes its rules for progress in the CTL of the temporal logic lectures. Safety needs nothing new: the safety properties of UNITY are sets built from AX and AG. Progress needs one operator, AfF, from part 2. We start with two rules about AfF, on any colored graph, and only then describe the model of computation of UNITY.

Builds on:Temporal logic part 1Part 2: until and fairnessPart 3: initial states, paths and LTL

1. Fair paths

We use the colored graphs of part 2. Every edge has a color, and every vertex has an edge of every fair color. A fair path is an infinite path in which every fair color appears infinitely often. In the figures of this lecture every color is fair. As in part 3, ⟦φ⟧ is the set of vertices at which the formula φ holds, V is the set of all vertices, and ¬P = V ∖ P.

AfF: on all fair paths, eventually
⟦AfF Z⟧ = {v | every fair path from v reaches Z}

The first vertex of a path counts, so Z ⊆ ⟦AfF Z⟧.

Two facts about fair paths are used below.

  1. A suffix of a fair path is fair. Drop the first k vertices of a fair path from v: what is left is a fair path from vk, because finitely many steps do not change which colors appear infinitely often.
  2. Monotonicity (part 2): Y ⊆ Z ⟹ ⟦AfF Y⟧ ⊆ ⟦AfF Z⟧.

2. The basis rule

Basis rule
P ⊆ ⟦AX (P ∪ Q)⟧ ∧ V = ⟦AfF ¬P⟧ ⟹ P ⊆ ⟦AfF Q⟧

If every edge from P ends in P or Q, and every fair path reaches ¬P, then every fair path from P reaches Q.

The second condition, V = ⟦AfF ¬P⟧, says that no fair path stays in P forever. It is the same as P ⊆ ⟦AfF ¬P⟧, because every vertex of ¬P is in ⟦AfF ¬P⟧ already.

Proof

Let v ∈ P, and take a fair path from v. By the second condition, the path reaches ¬P. Let w be its first vertex outside P, and u the vertex before w. Then u ∈ P, so by the first condition w ∈ P ∪ Q. Since w ∉ P, w ∈ Q. So every fair path from v reaches Q.

Both conditions are needed. Without fairness, a path could go round a cycle inside P for ever. Without the first condition, a path could leave P to a vertex outside P ∪ Q and never come to Q. Figure 1 shows both.

3. Transitivity

Transitivity
P ⊆ ⟦AfF Q⟧ ∧ Q ⊆ ⟦AfF R⟧ ⟹ P ⊆ ⟦AfF R⟧

If every fair path from P reaches Q, and every fair path from Q reaches R, then every fair path from P reaches R.

The rule follows from one law of AfF.

Law
⟦AfF AfF R⟧ = ⟦AfF R⟧

Reaching a vertex from which every fair path reaches R is as good as reaching R.

Proof of the law

⊇: Z ⊆ ⟦AfF Z⟧ for every set Z; take Z = ⟦AfF R⟧. ⊆: let v ∈ ⟦AfF AfF R⟧. A fair path from v reaches some w ∈ ⟦AfF R⟧. The rest of the path, from w on, is a fair path from w (fact 1), so it reaches R.

Proof of transitivity
P ⊆ ⟦AfF Q⟧ ⊆ ⟦AfF AfF R⟧ = ⟦AfF R⟧

The first step is the first condition. The second is monotonicity (fact 2) applied to the second condition, Q ⊆ ⟦AfF R⟧. The third is the law. All the reasoning about paths is in the law; the rule itself is set algebra.

4. Fair execution: the UNITY model

So far the graph was arbitrary. Now we describe the model of computation of UNITY. A program has a set of states, a set of initial states, and a finite set of actions. Each action is a function from states to states: in every state it has exactly one next state. An action that does nothing in a state takes that state to itself. How actions are written down comes later.

An execution starts in an initial state and runs for ever. At each step one action is chosen and executed. The choice is arbitrary, with one constraint, fairness: every action is chosen infinitely often.

A program is a colored graph
vertex = state    color = action    v →s s(v)

Each action s gives every vertex v exactly one edge of color s, to the state s(v). If s does nothing in v, the edge is a self-loop. Every color is fair.

So an execution is a fair path from an initial state, and ⟦AfF Q⟧ is the set of states from which every execution reaches Q. In UNITY, P ⊆ ⟦AfF Q⟧ is written P ↦ Q and read “P leads to Q”.

The basis rule for a program

In a program, the second condition of the basis rule holds when one action takes every state of P out of P. Write ⟦AXs Z⟧ for the set of vertices whose s-edge ends in Z.

One action suffices
P ⊆ ⟦AXs ¬P⟧ for some action s ⟹ V = ⟦AfF ¬P⟧

A fair path takes an s-edge infinitely often. If it stayed in P, its next s-edge would leave P. So no fair path stays in P for ever.

In Figure 3, take P = {0} and Q = {1}. Every edge from 0 ends in 0 or 1, and red takes 0 out of {0}. So by the basis rule {0} ⊆ ⟦AfF {1}⟧: every execution from 0 reaches 1. The adversary can delay red, but not for ever. In the same way, blue gives {1} ⊆ ⟦AfF {2}⟧ and red gives {2} ⊆ ⟦AfF {3}⟧, and transitivity gives {0} ⊆ ⟦AfF {3}⟧.

Notes

UNITY is described in K. M. Chandy and J. Misra, Parallel Program Design: A Foundation (Addison-Wesley, 1988). There the basis rule is stated with P ∧ ¬Q in place of P in its two conditions; the proof is the same.
