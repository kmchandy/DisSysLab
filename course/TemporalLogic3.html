Elements of Temporal Logic

Part 3. Initial states, paths, and the temporal logic LTL

Parts 1 and 2 defined temporal operators in terms of sets of vertices of a directed graph. Now we extend the definitions to infinite paths from a set of initial vertices. Then we define the path operators X, F, G and U in linear temporal logic LTL and finally show how LTL differs from CTL.

1. Initial states

Associated with each graph is a nonempty set I of vertices. We call vertices in I initial vertices. Paths in the graph start in a set S of vertices, exactly when:

Paths start in S
I ⊆ S

Only reachable vertices matter

Whether a vertex v is in one of these sets depends only on the paths from v, so only on the vertices in R({v}) and their edges. So whether I ⊆ S depends only on the part of the graph reachable from I, which is R(I). With I = {d}, R(I) = {b, d, f, g, h}: the vertices a, c, e, i and j could be deleted, or their edges changed, and no answer in the last column would change.

2. Properties of a path

Parts 1 and 2 defined each operator as a set of vertices. Inside each definition is a statement about paths. For example, AF Z is the set of vertices v such that every infinite path from v has the property “visits Z”. This part looks at that property of a single path on its own. Doing so leads to the temporal logic LTL.

Path and suffix
π = v0 → v1 → v2 → …    πi = vi → vi+1 → …

π is an infinite path. Its suffix πi is the path that starts at position i: drop the first i vertices. π0 = π.

A path property holds or fails on each infinite path. We write π ⊨ φ for “the path property φ holds on π”. The simplest path property is a set Z of vertices, which holds on a path when the path starts in Z:

π ⊨ Z ≡ v0 ∈ Z

2.1 Examples of path properties

Each example below is a CTL formula, so it gives a set S of vertices, and the graph with initial vertices I has the property when I ⊆ S. Read in English, each one is a statement about the paths that start in I. All the examples use the example graph of parts 1 and 2, with I = {a}. Recall from part 1 that P ⟹ Q is a predicate whose truth set is ¬P ∪ Q.

Example 1. P ⟹ AG X

Take P = {e} and X = {e, f, g, h}. Then AG X = {f, g, h}, and the truth set of P ⟹ AG X is ¬P ∪ AG X = {a, b, c, d, f, g, h, i, j}. It contains a, because a is not in P, so the graph has the property. But it has it only because the initial vertex is not in P. P ⟹ AG X checks only the initial vertices: it says nothing about vertices of P that a path from I reaches later.

Example 2. P ⟹ AG (P ⟹ AG X)

In English: if a path starts in P, then whenever it is in P, it stays in X from then on. The truth set is ¬P ∪ AG (¬P ∪ AG X) = {a, b, c, d, f, g, h, i, j}. Again a is in it only because a is not in P: a P ⟹ in front constrains only the paths that start in P. With I = {e}, both example 1 and example 2 fail: e is in P, and the edge e → j leaves X.

Example 3. AG (P ⟹ AG X)

In English: whenever a path from I reaches P, it stays in X from then on. The truth set is {b, d, f, g, h, i, j}, and a is not in it: the path a → c → e reaches e, and from e the edge e → j leaves X. In general, the graph has this property exactly when R(I) ∩ P ⊆ AG X.

3. X, F, G and U on a path

Each letter makes a new path property from old ones, by looking at the suffixes of the path.

X: next
π ⊨ X φ ≡ π1 ⊨ φ

X φ holds on a path when φ holds on the path from its second vertex. For a set Z: π ⊨ X Z ≡ v1 ∈ Z.

F: eventually
π ⊨ F φ ≡ πi ⊨ φ for some i ≥ 0

F φ holds when φ holds on some suffix. For a set Z: some vertex of the path is in Z.

G: always
π ⊨ G φ ≡ πi ⊨ φ for every i ≥ 0

G φ holds when φ holds on every suffix. For a set Z: every vertex of the path is in Z.

U: until
π ⊨ φ U ψ ≡ for some k ≥ 0: πk ⊨ ψ, and πi ⊨ φ for every i < k

For sets Y and Z: the path reaches Z, and every vertex before that is in Y.

On one path there is no “all paths” or “some path”: there is only the path. So F and G are duals through plain negation: a path does not visit Z exactly when it stays in ¬Z.

π ⊨ F Z ≡ ¬(π ⊨ G ¬Z)

Letters can be nested

Because F and G take any path property, they can be applied to each other:

  • G F Z: from every position, the path visits Z later. That is, the path visits Z infinitely often.
  • F G Z: from some position on, every vertex is in Z. The path eventually stays in Z.

A path in a finite graph that we can draw is a lasso: a prefix, then a cycle repeated forever. On a lasso, every vertex after the prefix is on the cycle. So G F Z holds exactly when some vertex of the cycle is in Z, and F G Z exactly when every vertex of the cycle is.

4. From paths back to vertices: A and E

A path property becomes a set of vertices by asking about all the paths from a vertex, or about some path:

A and E applied to a path property
A φ = {v | π ⊨ φ for every infinite path π from v}
E φ = {v | π ⊨ φ for some infinite path π from v}

A and E turn a property of paths into a set of vertices.

Every operator of parts 1 and 2 is one letter with A or E in front of it:

AX Z = A (X Z)    AF Z = A (F Z)    AG Z = A (G Z)    A[Y U Z] = A (Y U Z)
EX Z = E (X Z)    EF Z = E (F Z)    EG Z = E (G Z)    E[Y U Z] = E (Y U Z)

CTL and LTL In CTL, every X, F, G and U has an A or an E directly in front of it, so every step gives a set of vertices. In LTL, the letters X, F, G and U are combined freely into a path property φ, and a single A is put in front of the whole formula: a vertex has the LTL property φ when it is in A φ.

Initial states

Initial states play the same part as in section 1. A graph with initial vertices I has the LTL property φ when every infinite path from an initial vertex satisfies φ:

I ⊆ A φ

So this says: every infinite path that starts in I has the property φ. In CTL, the check is I ⊆ S for a set S built from A and E operators; in LTL, it is I ⊆ A φ, with the A outside.

G F: infinitely often

For G F Z, the LTL property and a CTL formula agree:

A (G F Z) = AG AF Z

A vertex v is not in A (G F Z) exactly when some path from v eventually stays in ¬Z forever: it reaches some vertex w and then follows an infinite path that avoids Z. That says w ∉ AF Z for some w reachable from v, which is exactly v ∉ AG AF Z.

5. Branching time and linear time

For F G Z the two logics differ. LTL is a linear-time logic: it judges one path at a time. CTL is a branching-time logic: from a vertex the paths branch wherever a vertex has more than one edge, and its operators can speak of the branches still open at each step.

Take three vertices a, b, c, with edges a → a, a → b, b → c and c → c, and Z = {a, c}.

  • LTL, A (F G Z): every infinite path from a either stays at a forever or goes a → … → a → b → c → c → …. Either way it ends up staying in Z, so a ∈ A (F G Z).
  • CTL, AF AG Z: AG Z = {c}, because from a the edge a → b leaves Z. The path a → a → a → … never reaches c, so AF AG Z = {b, c}, and a is not in it.

The computation tree from a vertex shows every path from it at once: the root is the vertex, and each node has a child for each edge out of its vertex. Every infinite path from the root is a branch of the tree.

At every visit to a, the future still branches: the path could still go to b. AF AG Z asks every path to reach a vertex from which no branch leaves Z. A (F G Z) asks only that each path, on its own, stop leaving Z.

In the other direction, AG EF Z (from every reachable vertex, some path still reaches Z) speaks of some path in the middle of the formula, which LTL, with its one A outside, cannot. The logic CTL* allows A and E anywhere, and contains both CTL and LTL.

Notes

Note: where the logics come from

Pnueli introduced temporal logic for reasoning about programs in 1977, in its linear-time form. Clarke and Emerson introduced CTL, and with it model checking, in 1981. Emerson and Halpern defined CTL*. Fairness in LTL is itself a path property, such as G F “the path takes an edge of color c”; in CTL it has to be added to the logic, as AfF was in part 2.
