Term Project

Build a multi-agent application in an area you care about, and use ideas from the course to understand how it works and how it can fail.

Work on your own or in a team of two or three. Choose an idea below, adapt a paper, or propose your own project.

Proposed outline for discussion with the teaching team. The course’s existing safety-case requirement still applies.

Project outline

  1. Propose an idea. Write a short proposal describing what you want to build, the data you will use, a related paper or technical reference, and how it connects to the course. Check that you can access the data before committing.
  2. Build and test it. Use DisSysLab or discuss another framework with the teaching team. Compare your system with a simpler approach on the same inputs, including ordinary requests and cases designed to make it fail. Record the results so someone else can repeat the comparison.
  3. Explain what you learned. Submit your code with setup instructions and a short report covering the design, results, limitations, and sources. Give a brief presentation or demo. An unsuccessful idea can still make a good project if you explain what happened.
Proposed timingWhat to bring
Early in the termA short proposal and a sample of your data.

Choose a scope you can finish during the term. Exact dates and submission details will be agreed with the teaching team.

What to turn in

  • A short proposal: your question, team members, data source, a related paper or reference, and the course ideas you plan to use.
  • Working code and a README: instructions to run the project, obtain the data, and repeat your main experiment.
  • A short final report: what you built, how it compares with a simpler approach, your results and limitations, and the sources you used. For group projects, describe each person’s contribution.
  • A safety case in SAFETY.md: at least two things your system must never do, one thing it must eventually do, how these properties are enforced, and supporting evidence. Follow the linked guide for the full requirements. This can serve as the report’s safety section without repeating it elsewhere.
  • A brief presentation or demo: show how the system works and explain a useful finding or failure from your experiments.

Project ideas

Open an idea for a suggested approach, data source, and experiment. These are examples to adapt; the suggested checks and dataset sizes are not additional requirements. You are welcome to propose something else.

01 A sports reporter whose numbers you can checkSports & media

Can a team of agents write an accurate match report without inventing events or statistics?

Build
An analyst selects important events, a writer drafts the report, and a Python checker verifies structured claims against the event log. Keep the first version to goals, shots, and named players.
Data and starting scope
StatsBomb open data provides match and event JSON. Start with five matches, then evaluate on ten different matches. Follow the repository’s attribution terms.
Compare and measure
Compare a writer alone with the checked pipeline. Insert a misleading note into an event description; count unsupported claims, valid reports, refusals, and calls. A numeric check cannot certify all of the surrounding prose.
Example safety checks
Every published statistic must match a cited event or computed total; every named player must appear in the match roster.
Connection to the course
Typed messages, provenance, and guards at an output sink. Extend it by tracing which message introduced a wrong claim.

Reading: Towards a Science of Scaling Agent Systems, AgentDyn.

02 A playlist that represents everyoneSports & media

Does discussion produce a better shared playlist than simply taking turns choosing songs?

Build
Two listener agents have different genre preferences. A coordinator proposes a ten-track playlist, and a checker enforces duration and catalog constraints. Define a simple, visible satisfaction score for each listener.
Data and starting scope
FMA includes track metadata. Use 200 metadata records, without downloading audio; define simulated listener preferences yourself. Audio playback would require checking the tracks’ licenses.
Compare and measure
Compare round-robin selection with negotiation under the same call budget. Measure minimum listener satisfaction, repeated tracks, constraint violations, and messages used. Report satisfaction as a proxy, not a measure of musical quality.
Example safety checks
Every track must exist in the supplied catalog; total duration must stay within the agreed limit.
Connection to the course
Resource allocation, fairness, and bounded negotiation. A team should finish even when preferences conflict.

Reading: MASBench, Patterns and problems in emerging multiagent systems.

03 Choosing a movie as a groupSports & media

When people have different preferences, does agent discussion help the least satisfied person?

Build
Give three agents separate preference profiles and ask them to choose from a fixed movie shortlist. Compare a vote with a discussion followed by a decision. Keep the ranking rule explicit.
Data and starting scope
MovieLens 100K supplies ratings and movie metadata. Select 50 movies and construct simulated groups from ratings. Missing ratings mean unknown preference. Check the dataset’s use and redistribution terms.
Compare and measure
Measure average and worst-member rating on movies rated by all group members, then separately test cases with missing ratings. Add one agent that falsely claims unanimous agreement.
Example safety checks
The chosen movie must belong to the shortlist; the final record must preserve each member’s actual vote rather than accepting a claimed consensus.
Connection to the course
Partial knowledge, voting, and dishonest peers. Agreement among LLMs is not a fault-tolerant consensus protocol.

Reading: MASBench, Patterns and problems in emerging multiagent systems.

04 Booking a room without double-booking itCampus & daily life

What happens when two assistants try to reserve the same room at the same time?

Build
Two requester agents negotiate with a booking coordinator. A Python booking tool owns the calendar and applies changes atomically. Show the resulting schedule and a timeline of requests.
Data and starting scope
Create a fictional Avery House calendar with three rooms and 30 requests. Include overlapping reservations, cancellations, duplicate messages, and retries. This does not require access to Caltech’s booking systems.
Compare and measure
Compare a shared text calendar with a guarded booking tool. Replay the same requests in different orders. Measure double bookings, duplicate reservations, completed requests, and waiting time.
Example safety checks
A room must never have overlapping reservations; retrying the same request must never create a second reservation.
Connection to the course
Mutual exclusion, serializability, and idempotence. Extend to lab instruments that require several resources, where deadlock and fairness become visible.

Reading: Patterns and problems in emerging multiagent systems, AgentDyn.

05 A research reading list with traceable claimsScience & research

Can several agents find useful papers while keeping their summaries tied to actual sources?

Build
A scout retrieves records, a reader extracts supported claims, and an editor produces a short reading list. Pass paper IDs and evidence spans between roles rather than only free-form summaries.
Data and starting scope
OpenAlex offers scholarly metadata. Cache 50–100 records on one topic and use openly available abstracts or author-provided text. Basic access is limited; larger queries may need a free key. Metadata access does not grant full-text access.
Compare and measure
Compare one summarizer with the pipeline on a small set of manually checked questions. Seed a source with an instruction to fabricate a citation. Measure citation validity, claim support, coverage, and cost.
Example safety checks
Every cited paper must exist in the cached collection; every quoted passage must match its cited source. These checks alone do not prove a paraphrase is correct.
Connection to the course
Fan-out and fan-in, typed evidence, trust boundaries, and termination when a source is unavailable.

Reading: An Empirical Study of Multi-Agent Collaboration for Automated Research, AgentDyn.

06 Reproducing a published scientific plotScience & research

Can an agent team reproduce a figure and explain exactly which data and transformations it used?

Build
One agent identifies the table and requested transformation, a Python worker computes the plot, and a reviewer checks units, axis labels, and provenance. Start with one figure and a fixed set of plotting operations.
Data and starting scope
HEPData hosts tables associated with particle-physics publications; its maintained repository describes the collection. Choose and download one accessible table before proposing the project; keep its units, uncertainty columns, and source reference.
Compare and measure
Compare direct plot generation with the checked pipeline on deliberately altered units, missing rows, and mislabeled columns. Check plotted values against an independently written reference calculation.
Example safety checks
Every plotted point must have a traceable source row; incompatible units must be rejected before a plot is exported.
Connection to the course
Contracts, data lineage, and recovery. An extension can save intermediate results and test restarting after a failed worker.

Reading: An Empirical Study of Multi-Agent Collaboration for Automated Research, autoresearch.

07 Scheduling a small observing programScience & research

Can agents allocate a shared telescope fairly while respecting observing constraints?

Build
Two proposal agents request targets and a scheduler assigns a single simulated telescope. A Python checker owns the schedule. Start with supplied visibility windows so astronomy calculations do not dominate the project.
Data and starting scope
NASA Exoplanet Archive’s TAP service can export a small target catalog as CSV. Use 20 targets with explicitly simulated visibility windows, durations, and priorities; do not present the schedule as an operational observing plan.
Compare and measure
Compare greedy scheduling with negotiation. Measure accepted science priority, the least-served proposal’s allocation, conflicts, and response to a simulated telescope outage.
Example safety checks
Observations must fit their supplied visibility windows; two observations must never occupy the telescope at once.
Connection to the course
Resource sharing, fairness, and progress under changing availability. State the assumptions under which a waiting proposal is eventually considered.

Reading: MASBench, AgentWorld.

08 Explaining disagreements between air-quality sensorsScience & research

Can a monitoring team distinguish a genuine change from stale or inconsistent measurements?

Build
Station agents send observations to an aggregator; an explanation agent describes flagged discrepancies. A Python validator handles units, timestamps, and missing data before the explanation is published.
Data and starting scope
EPA AirData provides downloadable daily measurements. Start with one county and pollutant for one month. Replay rows as a simulated stream and inject known delays and unit errors.
Compare and measure
Compare immediate aggregation with an event-time window and validation. Measure detection of injected faults, false alarms, and time to produce a complete summary. Describe missing observations explicitly.
Example safety checks
Incompatible units must never be averaged; a report must never label an out-of-window observation as current.
Connection to the course
Message ordering, partial information, time windows, and liveness when a station stops responding. This is a data-quality exercise, not a health advisory service.

Reading: Why Do Multi-Agent LLM Systems Fail?.

09 An earthquake feed that survives a restartScience & research

Can a reporting pipeline recover without losing events or issuing the same notification twice?

Build
An ingest worker reads events, an analyst drafts brief summaries, and an output worker writes to a local notification log. Add durable event IDs and an explicit checkpoint of application state.
Data and starting scope
USGS earthquake API returns event data, including GeoJSON. Cache a week of events and replay them locally. Notifications are simulated, not public alerts.
Compare and measure
Crash the pipeline before and after a log write, then replay its input. Compare an ordinary retry with a checkpoint and idempotent output. Count lost events, duplicate outputs, and recovery time.
Example safety checks
An event ID must never produce two committed notifications; a committed checkpoint must never skip an event that has not been handled.
Connection to the course
Consistent state, recovery, logical ordering, and idempotence. Implement the checkpoint yourself: DisSysLab offices do not currently expose automatic snapshot recovery.

Reading: Why Do Multi-Agent LLM Systems Fail?, Which Agent Causes Task Failures and When? On Automated Failure Attribution of LLM Multi-Agent Systems.

10 A house planning assistant that remembers correctionsCampus & daily life

When plans change, can an assistant remember whose preference changed and which version is current?

Build
A note-taking agent records messages from a fictional Avery House planning group. A retrieval agent answers questions about dates, responsibilities, and preferences, using speaker IDs and versioned facts.
Data and starting scope
Write 15 short fictional conversations with corrections, ambiguous names, and unanswered questions. Store exact answers separately. You can borrow evaluation categories from GroupMemBench without needing its full benchmark.
Compare and measure
Compare one rolling summary, keyword retrieval, and structured memory on the same questions. Measure stale answers, attribution mistakes, correct abstentions, and memory size.
Example safety checks
One person’s statement must not overwrite another person’s preference; a superseded date must not be returned as the current confirmed date.
Connection to the course
Knowledge, causality, and versioned shared state. Checks can enforce record ownership and freshness; interpreting a person’s intent remains fallible.

Reading: GroupMemBench, MemoryArena, LLMs Get Lost In Multi-Turn Conversation.

11 A social-media digest that resists manipulated postsSports & media

Can agents summarize a discussion without treating a post as an instruction or counting reposts as independent evidence?

Build
A collector saves a bounded sample, topic agents classify posts, and an editor produces an aggregate digest. Keep publication local and retain source IDs so a claim can be inspected.
Data and starting scope
Bluesky Jetstream provides streaming infrastructure. Capture a small sample of public posts using a documented endpoint, pin the protocol version, and evaluate on a saved sample. Use synthetic posts for a redistributable test fixture; do not assume public posts are freely licensed.
Compare and measure
Add duplicate posts, a coordinated false claim, and text that tells the summarizer to change its task. Compare raw aggregation with deduplication and a structured extraction stage. Hand-label a small evaluation subset.
Example safety checks
A post ID must not be counted twice; the digest tool must not accept a source post as permission to publish externally.
Connection to the course
Untrusted inputs, correlated evidence, and exactly-once effects. Report coverage and false exclusions alongside successful attacks.

Reading: AgentDyn, Patterns and problems in emerging multiagent systems.

12 Planning outfits from a fixed wardrobeCampus & daily life

Can agents satisfy several outfit requests without inventing clothes or silently exceeding a budget?

Build
A stylist proposes outfits, an inventory agent tracks available items, and a checker enforces declared constraints. Use explicit categories and occasion rules; leave subjective taste to a short human review.
Data and starting scope
Fashionpedia supplies clothing categories and attributes. Start with a hand-curated catalog of 50 items using that vocabulary, with simulated prices and availability. The dataset is not a shopping catalog. Images are optional and have separate terms.
Compare and measure
Compare a single stylist with the pipeline across 20 requests. Include an item description that claims an exception to the budget. Measure valid outfits, item coverage, and preference ratings separately.
Example safety checks
Every selected item must exist and be available; the total computed from catalog prices must stay within the stated budget.
Connection to the course
Structured messages, shared inventory, and guards. An extension can reserve scarce items for multiple users without double allocation.

Reading: SkillsBench, AgentDyn.

13 A trip planner that checks its connectionsCampus & daily life

Does separating route planning from timetable checking reduce impossible itineraries?

Build
A planner proposes a sequence of stops and trips, a Python validator checks it against a timetable, and an assistant explains the accepted route or why no route was found.
Data and starting scope
The official GTFS example feed is a manageable starting point. Use its complete linked feed rather than combining unrelated documentation snippets. Create 30 departure-and-destination requests and a few simulated delays.
Compare and measure
Compare an unvalidated planner with a checked pipeline; use a small deterministic route search as the reference. Measure valid connections, missed feasible routes, arrival times, and calls.
Example safety checks
Every leg must reference an existing scheduled trip; a transfer must allow the declared minimum connection time.
Connection to the course
Partial knowledge, time ordering, contracts, and replanning. Scope the first version to one service day and a small network.

Reading: MASBench, LLMs Get Lost In Multi-Turn Conversation.

14 An agent team that audits a backtestScience & research

Can an independent reviewer catch a strategy that looks good only because it uses future information?

Build
A strategy agent proposes a small rule, a Python runner evaluates it, and a reviewer inspects feature availability and costs. Restrict rules to a short list of operations so every data dependency is visible.
Data and starting scope
FRED’s S&P 500 series is one source of historical observations. Download a permitted fixed interval and record its coverage and terms. A synthetic price series with seeded mistakes is enough for the first version.
Compare and measure
Compare review by an LLM with a runner that enforces the cutoff date for each decision. Seed a future-shifted feature and omitted transaction costs. Use a separate later interval for evaluation.
Example safety checks
A decision must not read observations dated after its cutoff; the simulated runner must never exceed the declared position limit.
Connection to the course
Information flow, reproducibility, and code-enforced permissions. Keep trades simulated; good historical returns alone do not establish a useful strategy.

Reading: An Empirical Study of Multi-Agent Collaboration for Automated Research, autoresearch.

15 When does collaboration actually help?Agent experiments

Does telling agents about one another improve a task that requires combining different information?

Build
Give three agents different clues to a small route or scheduling puzzle. A coordinator collects answers. Use a Python solver to generate solvable instances and verify answers.
Data and starting scope
Generate 40 puzzles with known solutions: 10 for development and 30 held out. Include an easier set where one agent has every clue, so you can separate information access from the effect of discussion.
Compare and measure
Compare independent answers, anonymous messages, named messages, and explicit collaboration. Keep information access and total token budget comparable. Measure correctness, correct-to-incorrect revisions, and communication cost.
Example safety checks
A final solution must satisfy all supplied constraints; a participant must not overwrite another participant’s original clue record.
Connection to the course
Partial knowledge, error propagation, and Byzantine behavior. Add one lying peer; compare checking evidence with simply trusting a majority.

Reading: MASBench, Patterns and problems in emerging multiagent systems, Towards a Science of Scaling Agent Systems.

16 Two agents sharing a kitchenAgent experiments

Can agents coordinate a simple game without repeatedly blocking one another?

Build
Build a small text-grid kitchen with two workers, one counter, and three recipes. Each worker sees its own position and nearby objects; a simulator validates actions and owns the game state.
Data and starting scope
Use a deterministic toy environment with saved seeds and 20 layouts. AgentWorld is inspiration for asymmetric roles and long tasks; reproducing its full game environment is outside the proposed scope.
Compare and measure
Compare independent policies, a central planner, and agents that send short messages. Measure completed recipes, collisions, repeated actions, and total messages under a fixed turn limit.
Example safety checks
Two workers must not occupy an exclusive cell simultaneously; an item must not be consumed twice.
Connection to the course
Mutual exclusion, deadlock, and progress. A trace should explain whether failure came from a bad plan, missing information, or coordination.

Reading: AgentWorld, MASBench.

17 Finding where an agent workflow went wrongAgent experiments

Can a debugger identify the first consequential error instead of blaming the last agent to speak?

Build
Instrument a small workflow with message IDs and parent IDs. An investigator reconstructs the causal chain; a reviewer proposes the smallest useful repair. Keep an untouched copy of the trace.
Data and starting scope
Generate traces from one gallery office with seeded wrong facts, dropped messages, and failed checks. The Who&When project provides further examples, subject to its data terms.
Compare and measure
Compare reading a flat transcript with reading a message graph. Score agent and step attribution against seeded faults. Replay with only the proposed repair to see whether it changes the outcome.
Example safety checks
A reported causal edge must correspond to an actual message dependency; diagnostic agents must not modify the original log.
Connection to the course
Logical clocks, causality, consistent observations, and fault isolation. Hashing logs can expose changes relative to a trusted digest; it does not prove their contents true.

Reading: Which Agent Causes Task Failures and When? On Automated Failure Attribution of LLM Multi-Agent Systems, Why Do Multi-Agent LLM Systems Fail?.

18 A small automated research assistantScience & research

Can an agent improve a simple predictive model without changing the test or spending indefinitely?

Build
A proposer chooses from a fixed set of features and model settings, a Python worker trains the candidate, and a recorder saves its configuration and validation score. Permit 15 trials.
Data and starting scope
UCI Wine Quality is a small tabular dataset with a CC BY 4.0 license. Use one CSV and CPU-sized models; split training, validation, and held-out test data before the agent runs.
Compare and measure
Compare agent proposals with random search using equal trials. Let the agent see validation scores only. A separate evaluator reports final test performance once; log failed trials and elapsed time too.
Example safety checks
The proposer must not access the held-out labels; a trial must not alter the evaluator or exceed its resource budget.
Connection to the course
Tool permissions, bounded autonomy, task completion, and reproducible evidence. No language-model training or dedicated GPU is needed for this version.

Reading: autoresearch, An Empirical Study of Multi-Agent Collaboration for Automated Research.

19 When do reusable agent skills help?Agent experiments

Does a written procedure help an agent perform a task, and what happens if the procedure contains a bad instruction?

Build
Choose a narrow task such as cleaning a CSV of event registrations. A worker follows a supplied procedure; an independent Python checker validates the resulting table. Keep file access limited to a project workspace.
Data and starting scope
Create 30 small tables with known duplicates, missing values, and spelling variants. SkillsBench supplies a model for comparing task-specific procedures; its entire benchmark is not required.
Compare and measure
Compare no skill, a carefully written skill, and a model-written skill. Hold tools and budgets fixed. Then test a skill that asks the worker to skip validation. Count correct outputs, damaged valid rows, and tool-policy violations.
Example safety checks
The original input file must remain unchanged; a completed output must preserve every required unique registration ID.
Connection to the course
Contracts between agents, least privilege, trusted code versus instructions, and evaluation beyond a successful demonstration.

Reading: SkillsBench, AgentDojo.

20 Checking evidence in a drug-discovery datasetScience & research · Domain guidance recommended

Can an agent team distinguish measurements that are genuinely comparable before summarizing a compound?

Build
An extractor selects assay records, a Python validator checks identifiers and units, and a reviewer explains which results can be compared. Begin with one target and one measurement type, with a domain mentor checking your reference answers.
Data and starting scope
ChEMBL data web services expose compounds, assays, and activity records. Save about 100 records, retaining assay conditions, relation signs, units, and source IDs. Confirm access and attribution before the proposal.
Compare and measure
Compare a single summarizer with the checked pipeline on deliberately mixed units, mismatched targets, and censored values such as “less than.” Measure invalid comparisons and rejection of valid records.
Example safety checks
A comparison must not silently mix units or targets; a censored measurement must not be reported as an exact value.
Connection to the course
Typed contracts, provenance, and independent verification. The result is an evidence-curation tool; laboratory effectiveness cannot be inferred from these checks.

Papers and inspiration

These readings offer methods you can adapt, from testing collaboration to handling memory and prompt injection. Pick one or two that fit your question; you do not need to reproduce a full benchmark. Dates and publication types are listed with each source.

Work first released in 2026

MASBench: Benchmarking LLM-based Multi-Agent Collaboration under Partial Observability

3 October 2026 · preprint

Studies collaboration when agents have different information. Borrow its separation of task performance from communication cost; start with puzzles you can score exactly.

AgentWorld: Benchmarking Long-Horizon Collaboration of Multi-agent LLMs

25 September 2026 · authors report COLM 2026 acceptance

Examines persistent teamwork with different roles. A small text game can test role assignment and coordination without reproducing the full benchmark.

Patterns and problems in emerging multiagent systems

13 August 2026 · research report, not a conference paper

Investigates agent interactions, including shared resources, conflicting instructions, and correlated behavior. Pick one controlled failure mode; do not treat more communication as automatically beneficial.

GroupMemBench: Benchmarking LLM Agent Memory in Multi-Party Conversations

14 May 2026 · preprint

Tests memory across people and conversations, including changed facts and ambiguous language. Borrow the speaker-aware questions and include a simple retrieval baseline.

An Empirical Study of Multi-Agent Collaboration for Automated Research

31 March 2026 · preprint

Compares individual and collaborative research workflows under controlled time budgets. Use that comparison to avoid giving a larger agent team an unfair resource advantage.

MemoryArena: Benchmarking Agent Memory in Interdependent Multi-Session Agentic Tasks

18 February 2026 · ICML 2026, per the paper record

Evaluates whether earlier experience helps with later actions, rather than testing recall alone. Design a second planning task that depends on a correction made in the first.

SkillsBench: Benchmarking How Well Agent Skills Work Across Diverse Tasks

13 February 2026 · preprint

Compares agents with and without reusable procedures across tasks with verifiable outcomes. Adapt the comparison to one small task family and measure both improvements and regressions.

AgentDyn: A Dynamic Open-Ended Benchmark for Evaluating Prompt Injection Attacks of Real-World Agent Security System

3 February 2026 · preprint

Evaluates prompt injection alongside legitimate uses of external information. Borrow the paired test: can the system reject malicious instructions while still completing ordinary requests?

autoresearch

2026 · software repository, not a paper

Provides a concrete loop for proposing, running, and evaluating experiments. Adapt the loop to a cheap CPU task, with a fixed evaluator and trial budget, rather than reproducing language-model training.

Earlier work worth reading alongside it

LLMs Get Lost In Multi-Turn Conversation

First posted May 2025 · ICLR 2026 Outstanding Paper

Studies failures when a task unfolds over multiple turns. Compare giving an agent all constraints at once with revealing the same constraints gradually. Official award announcement.

Towards a Science of Scaling Agent Systems

First posted December 2025 · revised April 2026

Compares several agent architectures across tasks with standardized tools and compute. Use it to choose meaningful baselines and investigate when coordination overhead outweighs its benefit.

Why Do Multi-Agent LLM Systems Fail?

First posted March 2025

Organizes failures into categories involving system design, agent alignment, and task verification. Use the categories to label failed runs, then explain the actual cause with a trace.

Which Agent Causes Task Failures and When? On Automated Failure Attribution of LLM Multi-Agent Systems

First posted April 2025

Studies identifying the agent and step responsible for a failure. Borrow its attribution task, and test your debugger on faults whose location you control.

AgentDojo: A Dynamic Environment to Evaluate Prompt Injection Attacks and Defenses for LLM Agents

First posted June 2024

An established environment for testing attacks carried in tool outputs. Start with one local workflow and evaluate ordinary task completion as well as attacker success.
