Distributed Systems

This course is about building safe systems with multiple agents, some of which may be LLMs. The course emphasizes safety. We use temporal logic to prove that our algorithms do what they are specified to do, and we use systematic ways of testing multi-agent systems. We take particular care that the systems we create do not modify the environment in unintended ways.

  7. Lab: Safety and coordination in multi agent systems

    What can go wrong. Different types of agent coordination. LLM Skills. MCP connectors. Sub-agents and parallel agents.

    • Skills: packaged instructions that an agent loads when a task matches.
    • MCP connectors: how agents reach external tools and data, and the trust boundary that creates.
    • Permissions and sandboxing: what an agent may read, write, run or fetch, and why the default should be “no”.
    • Hooks: fixed code that runs before or after each tool call to block, log or check actions — a rule the agent cannot be argued out of.
    • Prompt injection: a web page or file that tells the agent what to do. Some inputs are adversarial, as in the Byzantine generals problem.
    • Human approval: which actions need a person to approve them.
