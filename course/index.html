Distributed Systems

This course is about enhancing safety of multi-agent systems in which agents may use LLMs.

This course

AI has changed computer science and many aspects of life. When you leave Caltech you are going to help determine the safety of multi-agent systems at this critical time. You are here to think for yourselves, explore, and prepare for a changing world in which safety and resilience will be critical.

  • The course is graded pass/fail
  • Collaboration is encouraged.
  • Use anything - AI, documents, videos - that helps you learn.
  • The course has homework, labs, and a project. The course has no mid-term or final. You will get a passing grade if you turn in your homework and project report.
  • Ensure that your projects do not use data that impinge on anybody's privacy. Follow the Caltech honor code.

Term Project

Build a multi-agent application in an area that interests you. Talk to people for whom you build applications. Consider building your application for people outside computer science - your family, biologists, economists, humanists.

Submit a short proposal after the first week; turn in a progress report later in the term, and turn in a final report and make a presentation at the end of term.

Project outline, ideas, and papers

The project's safety case

Alongside your application, describe how your application could be attacked and safety features of the application.

  1. Specify the application clearly. Your specification could be in English rather than in temporal logic. Think of the spec as a user manual. Clear specifications are an important part of safety.
  2. Describe possible attacks on your app and how your app prevents some or all of them.
  3. Give the evidence: the attacks you tried, the tests you ran, and the number of attacks that succeeded.

Preparation for the class

The course uses a distributed systems framework called DisSysLab designed specifically for teaching distributed systems algorithms. Install it on your computer and set up an API key for the LLM you want to use. You can also build applications using any framework you like, such as Claude Code, OpenAI, or OpenRouter.

Allow about an hour to install the software and work through the setup guide on your computer.

Part 3Shared Whiteboards

  1. Shared Whiteboard (Lab 2) - The case of the missing cake

    Three detectives, one piece of evidence each, and a shared whiteboard. No detective can solve the case alone. The class covers:

    • A whiteboard is a message to everyone: what replaces the connections you drew in Lab 1, and what you can no longer predict.
    • An event-driven board: no rounds; the board sends itself whenever it changes, at most one copy per detective.
    • How the board knows the talking has stopped: termination detection when one agent sees every message, and why a cap guarantees the office ends.
    • What happened on a real model: a board read note by note, stale reads, and the same team on the same evidence filling the board in a different order.
    • One more note on the fridge: an attack that needs no knowledge of the system framed nobody, but one detective's doubt reached the whole team.
    • Incidents as networks: agents in an OpenAI evaluation that broke out and into Hugging Face (July 2026), prompt injection in Copilot, GitHub and Slack, and poisoned models and extensions, each drawn as an office: where the input entered, which edges it travelled, and where a guard would have stopped it.

    Safety question. If one agent is wrong, how far does its mistake spread?

    The lab: the cake room. Run the detectives, read the board note by note, find where each one first names Cal, run it again and compare. Then build a whiteboard team of your own.

Part 6Agents that act

  1. Lab 3: Agents that act

    Agents made in plain English with Claude Code, on two small problems. The course staff run them and keep every trace; you read the agents, predict, and check the traces.

    • An agent is a file: instructions in English, the tools it may use, and permission rules that Claude Code enforces.
    • The one-dollar Tahoe, with a real booking: Lab 1's salesperson can now book a sale. Does one sentence of English keep it from a one-dollar sale? Where would a real check go?
    • A task that cannot be done: an agent told to make tests pass when two of them contradict each other. Does it say so, edit the tests, or game them?
    • Advice or a fence: a sentence of English against a permission rule, each run many times and compared.
    • Agents that break out, and agents that know they are being tested: the 2026 evaluation incidents at OpenAI and Anthropic, and why a test result is evidence only if the agent cannot tell the test from real use.

    Safety question. When an agent with tools is given a goal it cannot reach honestly, what does it do, and what stops it?
