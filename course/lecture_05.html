What Agents Know

An agent acts on what it knows. In a distributed system it knows almost nothing: its own state, and whatever arrived in a message. This class makes “agent X knows P” precise, for a predicate P about the rest of the system, and then proves four things about it. Every proof is the same proof — a consistent cut, from the previous class, and the dataflow graph from the one before that.

What is P about?

Fix an agent X. We ask what X knows about the network of other agents and the channels between them. P is a predicate on that network, and on nothing else: not on X, and not on the channels incident on X.

P can be “agents U, V and Z are deadlocked”, or “every agent is waiting for a message and every channel is empty”, or “W solved its problem”. Each is a statement about the region inside the oval in the figure below, and each is something X may or may not be in a position to assert.

What information enables X to know that W solved its problem?

Figure 1 said what P is about. It said nothing about how X could ever be in a position to assert it. X is not next to W; the two are not even joined by a channel. So if X knows that W solved its problem, something must have carried the news, agent by agent, until it reached X.

A controller and a furnace

A controller C sends control messages to a furnace F, and F replies with the action it took. The furnace is also called the plant. Four steps take the system from one state in which C knows the furnace is on to the next; in asynchronous VLSI this is the four-phase handshake.

The same handshake, drawn as a computation

The figure above shows states one at a time. Draw the whole computation instead, with a line for C and a line for F, and the intervals in which C knows something become segments of C's line. This is the dataflow graph of the previous classes: the nodes are steps, and an edge carries a state.

Two agents and two tokens

A smaller example, with nothing in it but counting. Two agents, X and Y, pass two indivisible tokens back and forth. What does X know about Y?

What “X knows P” means

Now the definition. Consider a point on X's line: an edge of the dataflow graph between two consecutive steps of X, labelled with X's state there. Call that state s.

Knowledge at a point X knows P when X's state is s means: P holds in every global state in which X's state is s.

That definition is about global states, and the previous class gave us the global states that matter: the consistent cuts. Many different cuts pass through one point on X's line, and they describe different global states — but X's own state is s in all of them, because they all cut the same edge of X's line. So the definition has a consequence we can draw:

Knowledge and consistent cuts If X knows P at a point on X's line, then P holds in the global state of every consistent cut through that point.

Losing knowledge, and gaining it

With the definition in hand the theorems are short, and they are all proved the same way: take two consistent cuts that are identical everywhere except at the agent in question, and notice that a predicate about the rest of the system cannot tell them apart.

Theorem An agent does not lose knowledge when it takes a step in which it sends no messages to other agents.

Theorem An agent does not gain knowledge when it takes a step in which it receives no messages from other agents.

And now the same picture with one thing changed: at step 5, C sends a message to U. The alarm it sends itself at 2 is still there and still harmless. What matters is the message that leaves C.

And the dual. Keep the same computation, but ask the opposite question: can the cut be walked forward across step 5? Step 5 receives only the alarm C sent itself, and nothing from another agent — which is the hypothesis of the second theorem.

Knowledge travels along paths

The next theorem is the one with teeth. If something becomes true somewhere in the system, and later an agent knows it, then there is a chain of messages from the one event to the other. Nothing is learned out of thin air.

Theorem If NOT Q holds before a step e, and C knows Q after a step e′, then there is a path in the dataflow graph from e to e′.

Two more, and a warning about negation

The same argument, run in the other direction, gives the mirror theorem: if C knows Q before a step e and NOT Q holds after a step e′, then there is a path in the dataflow graph from e to e′. Figure 3 is an instance — C knows the furnace is on, and the furnace is off only after the message C sent has arrived.

And one consequence worth stating on its own, because it is the shape of Figure 4:

Theorem If C knows Q before a step, and NOT Q holds after some later step, then there is a point in between at which C is uncertain about Q.

C cannot pass directly from knowing Q to knowing NOT Q. Something must happen, a message must travel, and while it travels C knows neither.

Finally, a distinction that is easy to lose. NOT (C knows Q) is not C knows NOT Q. The first is much weaker: it is satisfied either by C knowing NOT Q, or by C having no idea. That second case is what we have been calling uncertainty:

Uncertainty C is uncertain about Q means NOT (C knows Q) and NOT (C knows NOT Q).

Every “C uncertain” label in Figures 3 and 4 is that conjunction, and every one of them is produced by the same thing: a message that C has sent, or is waiting for, and cannot see.
