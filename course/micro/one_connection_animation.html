How a message gets from agent X to agent Y

Three queues, four independent actions. Nothing is synchronised.

What to notice

  • Each of the four actions happens on its own schedule. There is no clock that they share, and no step where two of them agree to move together. That is what asynchronous means here.
  • A message is only ever in one place: X's outbox, the channel, or Y's inbox. Nothing is copied and nothing is shared.
  • Set channel takes from the outbox to 0 and watch X's outbox fill up. X is now producing faster than the channel drains — and X cannot tell, because it can only see its own outbox.
  • Order is kept inside each queue: first in, first out. A message cannot overtake one ahead of it on this connection.
