Building offices

Every tool, document and library for building an office, in one place

An office is a distributed system written in English: agents, the roles they play, and the connections between them, in a file called office.md. The material for building offices is spread over the course pages, the documentation and the code. This page is an index to all of it. The lists of commands, roles, sources and sinks were read from DisSysLab 1.10.2; your own installation can always tell you its current lists (see each section).

Roles

A role is a job description: what an agent does to each message. In office.md you write, for example, Jay is a summarizer. DisSysLab looks for the role first in the office's own roles/ folder, then in the built-in library. Most roles are written in English (.md files, run by a language model); a role that must be exact is written in Python (.py).

Built-in roles

In dissyslab/roles/. dsl roles lists them; dsl show <role> prints one in full.

RoleWhat it adds or does
category_classifierOne of a fixed list of categories you set. Adds category.
confidence_filterPasses on only the messages whose confidence clears a threshold you set. Python; costs nothing to run.
entity_extractorThe people, organisations, places and events named in the item. Adds entities.
evaluatorWhether a written briefing is good enough to publish, and why not. Adds verdict, feedback; sends to publish or revise.
geolocatorWhere in the world the item is about: country and region. Adds location.
relevance_filterDecides whether an item is worth passing on. Sends to keep or discard.
sentiment_classifierPositive, negative or neutral, with a score from −1.0 to +1.0. Adds sentiment, sentiment_score.
severity_classifierHow significant the item is: CRITICAL, HIGH, MEDIUM or LOW. Adds severity.
summarizerOne plain-English sentence saying what the item is about. Adds summary.
summary_writerA short paragraph a busy reader can scan. Adds brief.
topic_taggerOne of eight topics, from politics to entertainment. Adds topic.
urgency_classifierHow time-sensitive the item is for the reader: HIGH, MEDIUM or LOW. Adds urgency.
writerThe item rewritten for a reader: a headline and a short briefing. Adds headline, summary.

Coordinators

A coordinator is an agent that holds messages still until a condition is met. It has no role file: its settings go on its own line, for example Sync is a synchronizer(inboxes=["a", "b"]).

CoordinatorWhat it doesSee it in
synchronizerWaits until it has one message on each of its inboxes, merges them into one message, and sends it on.room_climate_monitor, debate, periodic_brief_pro
selectFeeds one worker one message at a time. A message on its command inbox says which inbox to read next, so a worker waiting for a reply can hold the other queue still.returns_desk
gateAdmits one item at a time: it passes on a message, then waits for a message on its control inbox before admitting the next.debate
routerSends a copy of each message to every outbox whose rule it matches; a message that matches no rule is dropped.not yet in the gallery; see the grammar
recordKeeps shared data. Other agents read and update it by sending requests, so no agent needs shared memory. Used with a gate.investment_club (a test office)

The grammar describes each one. shipment_release shows a related idea built from an ordinary role: nothing is released until a scan and a manifest agree.
