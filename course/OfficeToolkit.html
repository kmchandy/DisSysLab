Building offices

Every tool, document and library for building an office, in one place

An office is a small distributed system: agents, the roles they play, and the connections between them, written in a file called office.md. This page is an index to everything you use to build one. The lists were read from DisSysLab 2.0; your own installation can always print its current lists, and each section says how.

Writing office.md

ResourceWhat it is
dsl grammarThe complete reference: sections, declarations, connections, routers, coordinators, nested offices, drafts, and what dsl check reports. It ships with DisSysLab, so it matches the version you have.
dsl grammar examplesFour gallery offices explained line by line: returns_desk, room_climate_monitor, situation_room_pro, debate.
Sense, think, respondThe shape most offices take: sources sense, agents think, sinks respond.

An office is agents, the roles they play, and the connections between them. office.md holds two of those three: who is in the office, and where each one's messages go. What each agent does, its role, and the role's contracts, live in its own file under roles/ (below). So office.md has just two kinds of line:

  • name: kind(args) says who is in the office. Under sources:, where messages come from; under sinks:, where they end; under agents:, each worker in between, with the role it plays (Felix: topic_filter) or the router or coordinator it is (Rex: router(on="on_topic")). Arguments are written as in a Python call.
  • a -> b says where messages go: every message a sends, b receives, in the order sent. Chains (a -> b -> c), fan-in (a, b -> c) and fan-out (a -> b, c, each getting its own copy) are shorthand for several such lines.

The news filter from the micro-course, whole:

sources:                              # who is in the office
    al_jazeera(max_articles=2)
    bbc_world(max_articles=2)

sinks:
    console_printer
    discard

agents:
    Felix: topic_filter               # an agent playing the role roles/topic_filter.md
    Rex: router(on="on_topic")

connections:                          # where messages go
    al_jazeera, bbc_world -> Felix -> Rex
    Rex.yes -> console_printer
    Rex.no -> discard

Every agent has one inbox and one outbox, so a -> b never names them. A dot is needed only where there is a choice: one of a router's ways out (Rex.yes), or one of a coordinator's inboxes (Gate.done).

Roles

A role is what an agent does: one JSON object in, JSON out. An annotator adds fields to the message; an author (kind: author) returns a list of new messages, and the message it received goes no further. A role is a prompt (.md, carried out by an LLM) or Python (.py, one class). Its front matter's in: and out: lines are its contracts. DisSysLab looks in your office's roles/ folder first, then in the built-in library. dsl grammar roles has everything.

To change a built-in role, dsl show it, copy it into your roles/ folder under a new name, and edit it there. Every gallery office has a roles/ folder of its own to learn from. Write a Python role walks through one, with tests and state.

Models

LLM agents use Anthropic's Claude unless you say otherwise. Choose per agent with ai=: Sam: severity_classifier(ai="ollama"). The names: anthropic (or claude), openai (gpt), gemini, openrouter, ollama (free, on your own machine), gemma, qwen; each also comes as _precise and _creative. dsl check rejects a name it does not know. LANGUAGE_MODELS has the keys each needs.

Contracts and guardrails

A model can be wrong, and it can be talked into things. Contracts do not make it right; they stop what it gets wrong from spreading. They are optional, they are checked by Python on every message, and no model can argue with them.

WhereCheckedIf it does not fit
in: of a roleeach message, before the role is calledrefused: an LLM never sees it
out: of a roleeach replyrefused: the reply goes no further
in: of a sink you writeeach message, before the sink actsrefused: the sink does not act on it

A refusal may be an attack, so it stops the whole office: no role runs again, sources stop, and work finished before it is kept. The run summary ends with Stopped:, naming the agent and the reason; the message, the reason and any reply are written to refused.jsonl in the office's folder; dsl run exits non-zero. To handle refusals instead, connect the agent's refused outbox (Clerk.refused -> Log): the refused message goes there, with a field refusal giving the reason, it is still recorded, and the office carries on. (Fields a reply carries but out: does not declare are only dropped, and named in the summary.) A field in in: or out: may say what it holds:

WrittenMeans
verdict (publish | revise)one of these values
price (number)a number (the text "62400" is not one)
score (0..10), price (number, >= 0)a number in a range, ends included
count (integer, 1..5)a whole number
reply (text, at most 600 chars)text no longer than that

Beyond contracts:

  • An author with out: is a barrier. Only the fields it lists leave it, so a customer's or a web page's words stop there. An annotator is not a barrier: the message it passes on keeps them.
  • A Python agent in front of a sink checks what a contract cannot say, such as a price above the floor for that car. Lab 1 builds one.
  • dsl check notes, before anything runs: text from strangers (news, email, a chat page) that can reach a sink that acts in the world; Python that reaches the network; a router value with nowhere to go.
  • The stall report, when an office goes quiet: who is still waiting, and on which inbox. A refused message can leave a coordinator waiting for ever.

dsl grammar roles has the full rules; your own sinks are at the end of dsl grammar sources.

AI help

dsl new builds an office from a description, by chatting with Claude; dsl edit changes one. Both give the model the same reference dsl grammar prints, run dsl check on what it writes, and send the problems back to it. Read what it wrote, and dsl check . again, before you run it.

You are welcome to use an AI assistant in this course, and it will be wrong about this framework in ways you cannot detect, because it has read a thousand others. These four commands answer from your own installation, which is the version you are actually running:

dsl grammar     # what office.md is allowed to say
dsl roles       # every role that ships, and what it adds
dsl list        # every office that ships, to copy and read
dsl doctor      # what is installed, and whether it is stale

A habit worth forming: when an assistant tells you something about an office, ask it which command it read that from. If it cannot say, it did not read it.
